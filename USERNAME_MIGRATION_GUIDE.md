# Username Field Migration Guide

## Overview
This guide documents the changes made to add username support to the ProsperMentor application and ensure backward compatibility with existing data.

## Problem
The Supabase database trigger that creates user profiles was failing because the `username` column had a NOT NULL constraint, but the trigger wasn't providing a username value when creating new profiles.

**Error**:
```
null value in column "username" of relation "profiles" violates not-null constraint
```

## Solution

### 1. Application Code Changes

#### Profile Entity (`Profile.java`)
- Added `username` field as a required, unique column
- Location: `src/main/java/com/prosper/prospermentor/entity/Profile.java:42`

```java
@Column(name = "username", nullable = false, unique = true)
private String username;
```

#### SupabaseAuthService (`SupabaseAuthService.java`)
Added automatic username extraction from email addresses:

- **New helper method**: `extractUsernameFromEmail()` - Extracts the part before @ symbol
  - Example: `jabezemmanuel55@gmail.com` → `jabezemmanuel55`

- **Updated methods** to include username in user metadata:
  - `createMinimalUser()` - Line 147
  - `createUser()` - Line 101
  - `signUpWithPassword()` - Line 318

### 2. Database Migrations

#### V25: Update Profile Creation Trigger
**File**: `src/main/resources/db/migration/V25__Update_profile_creation_trigger_for_username.sql`

Updates the `handle_new_user()` function to:
- Extract `username` from user metadata (raw_user_meta_data or raw_app_meta_data)
- Fallback to email prefix if username not in metadata: `SPLIT_PART(email, '@', 1)`
- Extract `first_name` and `last_name` from metadata (supports both snake_case and camelCase)
- Explicitly set username when creating profile to prevent the existing `generate_username_from_name` trigger from running

#### V26: Backfill Existing Usernames
**File**: `src/main/resources/db/migration/V26__Backfill_existing_usernames.sql`

Ensures backward compatibility by:
1. **Counting** existing profiles with NULL usernames
2. **Temporarily removing** NOT NULL constraint if needed
3. **Backfilling usernames** using this priority:
   - If `first_name` AND `last_name` exist: `{firstName}_{lastName}_{id_prefix}`
   - If only `first_name` exists: `{firstName}_{id_prefix}`
   - Otherwise: `{email_prefix}_{id_prefix}`
4. **Handling duplicates** before adding unique constraint
5. **Restoring** NOT NULL constraint
6. **Adding** unique constraint on username column

## Migration Order

The migrations must run in this order:
1. **V25** - Updates the trigger for new user creation
2. **V26** - Backfills existing profiles and adds constraints

## How to Apply Migrations

### Option 1: Via Supabase SQL Editor (Recommended for immediate fix)
1. Go to Supabase Dashboard → SQL Editor
2. Run V25 migration first:
   - Copy contents from `V25__Update_profile_creation_trigger_for_username.sql`
   - Paste and execute in SQL Editor
3. Run V26 migration second:
   - Copy contents from `V26__Backfill_existing_usernames.sql`
   - Paste and execute in SQL Editor

### Option 2: Via Spring Boot Application Startup
The migrations will run automatically when you start the Spring Boot application, as Flyway is configured to run on startup.

## Username Generation Logic

### For New Users (via trigger)
The trigger maintains **full backward compatibility** with your existing `generate_username_from_name` function:

```
Priority:
1. metadata.username (if explicitly provided in metadata)
2. metadata.app_metadata.username (if explicitly provided)
3. If first_name AND last_name provided:
   → Set username to NULL → Let generate_username_from_name trigger handle it
4. Otherwise: SPLIT_PART(email, '@', 1) (email prefix fallback)
```

**Example scenarios**:
- Email: `john@example.com`, Metadata: `{firstName: "John", lastName: "Doe"}`
  → Username generated by `generate_username_from_name("John", "Doe", id)`

- Email: `jabezemmanuel55@gmail.com`, Metadata: `{username: "jabezemmanuel55"}`
  → Username: `jabezemmanuel55` (from metadata)

- Email: `test@example.com`, Metadata: `{}`
  → Username: `test` (from email prefix)

### For Existing Users (backfill via V26 migration)
The backfill uses the **same** `generate_username_from_name` function for consistency:

```
Priority:
1. generate_username_from_name(first_name, last_name, id) - if both names exist
2. generate_username_from_name(first_name, '', id) - if only first name exists
3. {email_prefix}_{id_prefix} - fallback for profiles without names
```


## Notes

- Username is now required and unique for all profiles
- Existing Supabase trigger `generate_username_from_name` will not run when username is explicitly set
- The solution maintains backward compatibility with existing data
- All new user creations will automatically include username in metadata
